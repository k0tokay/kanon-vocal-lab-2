# 声道解剖の変更と調音補償

嘉音の解剖パラメタは、成人の解剖からかなり離れている。調音がうまくいかないのはそのせいかもしれない。そこで、解剖を現実的な値へ動かしながら、/a i u/ の F1–F3（9次元）を保つように調音を追従させた。

使う写像は、解剖（13）と3母音の調音（16 × 3）から、9つの対数フォルマントへの写像である。そのヤコビアンの核（等フォルマント面の接空間）に沿って、解剖を目標まで直線で動かす。

共通部品は [../vtlmap](../vtlmap/README.md) に置いた。

## 方法

- **解剖**：VTL の `AnatomyParams`（GUI の Anatomy parameters の13項目）。`setFor` は、組み込みの基準話者を伸縮して声道を作る。
  - 嘉音の13値から作った声道は、元の話者ファイルと同じフォルマントを出す。
  - 目標は2つ。
    - **W02**：`W02.speaker` から読んだ13値。
    - **F15**：GUI の High-level parameters で「15歳・女性」にした値（`calcFromAge(180, female)`）。
- **調音の座標**：基準話者の座標で書く。そのため「補償なし」は、VTL が解剖変更時に行う形状の伸縮（`adaptArticulation`、GUI と同じ）になる。補償量は、その伸縮からのずれとして読める。
  - 自由変数は TRX, TRY（自動計算）と VO（閉じたまま）を除く16個。
  - それぞれ基準話者の可動域で [0, 1] に正規化した。
- **積分**（`vtlmap.follow`）：
  - 予測子：J_調音 dq = −J_解剖 dθ の、範囲つき最小ノルム解。
  - 修正子：解剖を固定した Levenberg–Marquardt 法。
  - 許容誤差：各フォルマントで 0.5%。
  - 制約：舌側面の底上げ前の最小断面積を 0.12 cm² 以上とし（接触の判定、[vowel-topology](../vowel-topology/README.md) と同じ）、外れた点は棄却して刻みを半分にする。
- **フォルマント**：8192 点（5.9 Hz 刻み）の伝達関数のピーク。
- **差分**：範囲の 1% 刻みの minmod 差分。

2通りを解いた。

- **厳密**：嘉音の9つのフォルマントをそのまま保つ。
- **スケール込み**（`--scale`）：9つすべてに共通の倍率 k を自由にする。体の大きい人が同じ母音を言う場合にあたる。k も自由変数として最小ノルムに入る。

## 結果

**目標の解剖が自分の母音で出すフォルマント**（[baseline.py](baseline.py)、Hz）

| | /a/ F1–F3 | /i/ F1–F3 | /u/ F1–F3 |
|---|---|---|---|
| 嘉音 | 854 1530 3651 | 472 2572 3726 | 429 1264 3422 |
| W02（自身の形状） | 705 1098 2904 | 327 2431 3438 | 385 800 2543 |
| 女性15歳（VTL 標準母音を伸縮） | 737 1377 2844 | 328 2501 3415 | 329 786 2931 |

嘉音のフォルマントは、どちらの目標の解剖が自然に出す値よりも全体に高い。特に /a/ の F2・F3 と /i/ の F1 が高い。

**積分の到達点**

| | 到達した s | 止まった理由 | 共通倍率 k |
|---|---:|---|---:|
| W02 厳密 | 0.25 | /u/ の最小断面積が 0.12 cm² に達した | — |
| F15 厳密 | 0.71 | /a/ の顎角 JA が開口の端に達し、F1・F3 を保てない | — |
| W02 スケール込み | 0.46 | 修正子が 0.5% 以内に戻せない | 0.912 |
| F15 スケール込み | **1.00** | 到達 | 0.877 |

s = 0 が嘉音、s = 1 が目標の解剖。止まった場合、出力の話者ファイルとWAVは、止まった時点の解剖のものになる。

- **補償なし（VTL の伸縮だけ）**：フォルマントは急に動く。W02 へ向かうと、s = 0.1 で /u/ の F1 が −11%、s = 0.175 で −38% ずれる。s ≈ 0.2 以降は、/u/ のピークが1つ消えて F1–F3 がそろわない（[W02/path.png](results/W02/path.png)）。
- **厳密に保つ場合**：
  - W02：/u/ は狭めをどんどん細くするしかなく、接触の境界で止まる。
  - F15：/a/ が補償の大半を担う。顎と唇を大きく開き（JA −0.31、LD +0.40、LP −0.27）、それでも足りなくなって止まる（[F15/params.png](results/F15/params.png)、[F15/outlines.png](results/F15/outlines.png)）。
- **スケール込みの F15**：
  - 補償は各範囲の 10% 以下と小さい。
  - 目立つのは /u/ の舌体の前進（TCX +0.11）と /i/ の舌体の下降（TCY −0.07）だけである（[F15-scaled/params.png](results/F15-scaled/params.png)、[F15-scaled/outlines.png](results/F15-scaled/outlines.png)）。
  - 補償なしでは /u/ のフォルマントが途中で崩れるので、/u/ だけは補償が要る。
  - 到達点のフォルマント（Hz）：

    | | F1 | F2 | F3 |
    |---|---:|---:|---:|
    | /a/ | 749 | 1342 | 3204 |
    | /i/ | 414 | 2257 | 3268 |
    | /u/ | 376 | 1109 | 3002 |

    嘉音の値の 0.877 倍で、母音の比は保たれている。

読み取れること：

- 嘉音の母音の配置そのもの（比）は、15歳女性の解剖で、VTL の標準的な調音からわずかにずらすだけで出せる。
- 嘉音の高さ（絶対値）を保とうとすると、成人寄りの解剖では /a/ の過剰な開口や /u/ の接触寸前の狭めが要る。この「無理」は、解剖の小ささとフォルマントの高さが組になって決まっているところから来ている。
- W02 の13値は、W02 そのものの声道を再現しない。W02 の形状を13値から作り直した解剖に載せると、/i/ の F3 が 3438 → 2574 Hz に下がり、/u/ はピークが3つそろわない。そのため W02 を目標にした結果は、「W02 の解剖」ではなく「W02 の寸法に伸ばした基準話者」に向かったものとして読むこと。

## 試聴

各フォルダに、/a i u/ の静止母音（F0 220 Hz）を置いた。

- `naive.wav`：止まった時点の解剖で、VTL の伸縮だけを行ったもの。
- `compensated.wav`：補償したもの。

[results/kanon.wav](results/kanon.wav) が元の嘉音。

各フォルダの話者ファイル：

- `kanon-<目標>.speaker`：a, i, u を補償した形状にし、他の形状は VTL の伸縮で移したもの。
- `kanon-<目標>-naive.speaker`：すべての形状を伸縮したもの。

声門モデルは嘉音のまま（声帯長の解剖パラメタは声門モデルの設定に影響しない）。

## 既知の限界

- 音響空間は /a i u/ の F1–F3 だけで、子音は入っていない。
- 解剖の経路は13次元空間の直線に固定した。解剖自体も核に沿って動かせば、もっと遠くまで行ける経路があるかもしれない。
- 最小ノルムの重みは「各パラメタの可動域を1」としただけで、調音の労力や自然さの尺度ではない。
- スケール込みの W02 が s = 0.46 で止まった原因（どの母音の、どの制約か）は、まだ詳しく見ていない。
- 聴取での評価はしていない。

## 再現

```sh
clang++ -shared -fPIC -std=c++14 -O2 -w -Ibackend experiments/vtlmap/vtlmap.cpp $(ls backend/*.cpp | grep -v SoundLib.cpp) -o build-mac/vtlmap.so
cmake --build build-mac/gui --target VocalTractLabApi
python3 experiments/anatomy-compensation/compensate.py W02 F15
python3 experiments/anatomy-compensation/compensate.py --scale W02 F15
python3 experiments/anatomy-compensation/plot.py W02 F15 W02-scaled F15-scaled
python3 experiments/anatomy-compensation/baseline.py
```

1回の積分は、手元の macOS で 10〜30 分かかる。目標ごとに別のプロセスで並列に回せる。
